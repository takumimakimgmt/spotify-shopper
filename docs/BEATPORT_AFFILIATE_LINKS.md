# Beatport Store attribution

Purchase links follow the URL generated by the account's official Deeplink generator on 2026-11-05:

- Endpoint: `https://pluginboutique.postaffiliatepro.com/scripts/hfwq3c89wu2`
- Campaign: Beatport Store, `a_cid=0be88686`
- Affiliate: existing `NEXT_PUBLIC_BEATPORT_A_AID` (public referral ID)
- Destination: the full HTTPS Beatport search or product URL in `desturl`

The account-specific endpoint and campaign live in `lib/affiliates/beatport.ts`. If the affiliate account or campaign changes, regenerate a link in the official panel and update these values together; changing the affiliate ID alone does not establish campaign eligibility.

Saved direct URLs and this exact tracker URL are accepted. Before display, unwrap one tracker layer and validate an HTTPS destination on beatport.com or www.beatport.com without credentials. Nested trackers and other destinations are rejected. Rebuild with the current affiliate ID so restored links are not nested and retain their search/product labels. Bandcamp links are unchanged. Without a configured affiliate ID, direct Beatport links remain usable.

Verification: tests compare output byte-for-byte with the official generator sample, round-trip Unicode and search delimiters, preserve product links in Buy Later, and reject unsafe destinations. A prior single request to the supplied official sample returned HTTP 301 to the specified Beatport search and a Set-Cookie response. This confirms redirect/cookie response only; it does not prove a browser accepted the cookie, a click was credited, or a sale commission will be approved.

After deployment, use a normal browser to click an actual app link once, then check the affiliate panel's click report and Beatport Store campaign. Final purchase attribution requires an eligible real transaction and confirmation in the panel; no automatic or self-referral test purchases are performed by the app.
